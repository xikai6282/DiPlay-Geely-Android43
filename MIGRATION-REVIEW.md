# DiPlay 0.2.10 Android 4.3 (API 18) migration review

## Scope and identity

This work starts from the user's `DiPlay-0.2.10-source.zip`, not the older 0.2.9 checkout. The application release identity in `mobile/build.gradle.kts` remains `applicationId = com.shihab.diplay`, `versionCode = 29`, `versionName = 0.2.10`, with `minSdk = 18`. The debug variant intentionally adds `.hudtest` and `-hud-test`; a debug install therefore displays a test suffix while retaining code 29. Multidex remains enabled because Android 4.3 does not provide native multidex.

The migration keeps 0.2.10 behavior and adds API-gated implementations for older Android. It does not raise `minSdk`, globally suppress `NewApi`, or pull modern-only types into the API 18 launch path. Media3 remains an API 23+ video path; on API 18, a video request is rejected with a diagnostic instead of loading the Media3 activity. Optional Android Auto/map surfaces report unsupported when their platform APIs are absent.

## Compatibility changes by subsystem

| Source area | Compatibility entry points and API boundary | API 18 behavior |
| --- | --- | --- |
| `shared/.../compat/ContextCompat.kt` | `checkSelfPermission()` uses `Context.checkSelfPermission()` from API 23 and `checkCallingOrSelfPermission()` below it. `signatures()` uses `PackageInfo.signingInfo` from API 28 and the legacy signatures array earlier. | Host permission checks and accessory signature lookup avoid resolving newer methods on Android 4.3. |
| `shared/.../compat/UsbCompat.kt`, `transport/LegacyUsbTransfer.kt`, `transport/UsbDeviceLayout.kt` | Timed `UsbRequest.requestWait(timeout)` is restricted to API 26+. Synchronous bulk transfers use a single deadline, advance the buffer offset after short writes, and split writes into at most 16 KiB chunks on API <28. The descriptor reader parses the selected configuration and interface/endpoint descriptors rather than assuming configuration 1. | USB uses the legacy synchronous path without an infinite `requestWait()`. Invalid or missing configuration descriptors are rejected. NCM alternate settings and endpoint addresses are derived from the descriptor data. |
| `shared/.../transport/IphoneUsbHost.kt`, `NcmUsbBridge.kt` | Production USB host and NCM paths call the compatibility transfer/layout helpers. `requestWait(timeout)` and newer USB APIs remain behind SDK checks. | iPhone USB discovery and NCM operation use API 18 calls while preserving 0.2.10 USBMUX framing and boundaries. |
| `shared/.../network/VpnTunnelCompat.kt`, `CarPlayVpnService.kt` | `VpnService.Builder.setBlocking()` is API 21+. The API 18 path leaves the TUN descriptor nonblocking and routes reads/writes through `VpnTunnelCompat`, which retries EAGAIN with bounded backoff and preserves complete packets. Closing wakes the reader and stops idle polling. | VPN setup, packet I/O, and teardown work without calling `setBlocking()` or leaving a busy loop. |
| `shared/.../network/CarPlayBonjour.kt`, `vendor/jmdns/` | Effective mDNS mode is consistently `requested || SDK < 21` for both publishing and discovery. JmDNS endpoint deduplication compares the full endpoint and accepts TXT/address/port updates; removal clears by service name. Vendored JmDNS 3.6.3 binds multicast sockets in unbound → reuse-address → bind order. | JmDNS is used on API 18 instead of Android's API 21 NSD classes. The 0.2.10 dynamically selected AirPlay port remains the published endpoint; it is not replaced with a fixed port. |
| `shared/.../compat/Base64Compat.kt`, `CharsetsCompat.kt`, `NetworkInterfaceCompat.kt`, `ConcurrentHashMapCompat.kt`, `SystemServices.kt`, `PendingIntentCompat.kt`, `compat/WildcardBind.kt` | Compatibility helpers avoid API 19+ charset/Base64 types, newer `NetworkInterface` calls, default map/set methods, and newer service/intent APIs in API 18 call paths. Wildcard binding uses the legacy-compatible address path. | Common protocol, network, and diagnostic code can load without newer Java/Android library calls. MIME Base64 output retains 64-column line wrapping and round-trip behavior. |
| `shared/.../media/CodecCompat.kt`, `media/ModernAudio.kt` | Codec capability queries that require API 21+ run in guarded helpers. `ModernAudio` isolates `AudioAttributes.Builder`, `AudioFormat.Builder`, and builder-based `AudioTrack`/`AudioRecord` APIs (API 23+) and is entered only when `modernAudioSupported` is true. | Legacy codecs and legacy audio constructors remain available. Unsupported modern audio routing falls back to the old stream/track behavior. |
| `shared/.../media/VideoDecodeQueue.kt`, `transport/Iap2*` | Queue cleanup uses iterator removal instead of Java's newer `removeIf()` default. iAP2 channel/session resources implement `java.io.Closeable` rather than API 19 `AutoCloseable`. | Queue overflow continues to signal resynchronization, and USB/iAP2 objects can be closed by old runtime code. |
| `shared/.../airplay/NtpClock.kt` | NTP conversion normalizes negative nanoseconds with division/remainder arithmetic instead of API 24 `Math.floorDiv/floorMod`. | Negative timestamps preserve floor semantics on API 18. |
| `shared/.../transport/LockdownTlsEngineFactory.kt` and related pairing code | TLS endpoint-identification configuration is only applied on runtimes that provide `SSLParameters.setEndpointIdentificationAlgorithm`; the older path retains certificate/pair-record checks. | TLS pairing no longer throws `NoSuchMethodError` on API 18. The lock-down and MFi identity checks remain active. |
| `common/.../ModernSession.kt`, `CarPlayMediaKeys.kt` | API 21+ `MediaSession` use is isolated in `ModernSession`. The older branch uses `RemoteControlClient` and legacy media-button receiver registration, with play/pause/stop state publication and focus/receiver cleanup. | System media keys remain usable on API 18. Modern metadata/artwork state remains available on newer Android without replacing the bounded artwork queue. |
| `common/.../CarPlayVideo.kt`, `CarPlayVideoActivityBridge.kt`, `CarPlayVideoActivity.kt` | `CarPlayVideo.show()` rejects the API 18 path before launching the API 23+ Media3 activity. The host references an API-neutral bridge rather than an activity field typed to a Media3-owning class; the launch target is resolved by class name only after the SDK check. | Loading the host does not verify/load Media3 classes. A remote video request on API 18 fails with a bounded diagnostic. API 23+ continues through the existing Media3 player and public bridge operations. |
| `common/.../DiPlayActivity.kt`, `CarPlayHostActivity.kt`, `CarPlayVideoActivity.kt` | UI tint APIs and `RippleDrawable` are guarded at API 21; accessibility live-region behavior at API 19; seek-bar modern tinting and state-list animation at their supported levels. Permission checks use the shared helper. `finishAndRemoveTask()` is API 21+ with `finish()` fallback; `MotionEvent.actionToString()` is API 19+ with numeric fallback. | Settings/home/host UI uses simple legacy colors and platform widgets, while newer appearance remains on supported devices. |
| `common/.../CenterMapOverlay.kt`, `RoundedClipCompat.kt` | Overlay permission checks use `Settings.canDrawOverlays()` only from API 23; API 18 uses the legacy overlay permission/type path. `ViewOutlineProvider` and `clipToOutline` are isolated in `RoundedClipCompat.apply()` guarded at API 21. | The overlay can use its rectangular fallback without loading the API 21 anonymous outline class. Newer versions retain rounded clipping and 0.2.10 pinch behavior. |
| `common/.../ClusterMapPresentation.kt`, `MapEmbedService.kt` | API 19 `FrameLayout.LayoutParams` copy construction is replaced by explicit width/height/gravity/margin copying. `MapEmbed.release()` is guarded at API 30. `Message.sendingUid` is read only on supported versions; older map embedding returns its unsupported response. | Cluster/map surfaces do not fail class or method resolution on API 18. |
| `common/.../HomeScreenMonitor.kt`, `DiLink51ClusterMonitor.kt` | Usage-stats and AppOps framework types are isolated behind API 21+ helper classes. Monitor startup returns unsupported below API 21 rather than creating a poller. | No hidden usage-stats polling is started on API 18; optional cluster monitoring stays unavailable without affecting the main host. |
| `common/.../CarPlayHostActivity.kt`, `DiPlaySessionService.kt` | The host chooses `startForegroundService()` only from API 29 and `startService()` below it. The service uses the legacy `Notification.Builder(Context)` below API 26; channel-aware notification construction and foreground service type flags are isolated to newer SDK branches. | API 18 starts a regular service and builds a pre-channel notification before calling the two-argument `startForeground()`. |
| `shared/.../network/ManualHotspotManager.kt`, `LocalOnlyHotspotManager.kt`, `WifiP2pGroupManager.kt` | `activeNetwork`/link-properties, hotspot, P2P, location, frequency, and channel-close calls are individually gated at their platform API levels. Newer hotspot builder overloads are confined to supported branches; legacy paths keep their existing permission/security handling. | The legacy manual hotspot/transport selection path remains available. Unsupported hotspot/P2P capabilities fail clearly and do not prevent USB mode. |
| `common/.../HotspotUiLabels.kt`, host status strings, overlay title resources | UI labels are resolved from Android string resources while internal backend values and protocol/diagnostic identifiers remain stable. | API 18 displays localized hotspot labels and host/overlay state text. `Wi-Fi P2P` represents this device acting as the Wi-Fi Direct group owner (`WifiP2pGroupManager.createGroup`/`isGroupOwner`); it does not mean the iPhone is the hotspot. |

## 0.2.10 behavior retained

- USBMUX message framing and the security boundary that validates packet lengths and channel state.
- Runtime AirPlay port selection and publication of the actual bound port through Bonjour/iAP2.
- Bounded, stale-aware artwork delivery and asynchronous diagnostics with private payloads excluded.
- Safe video URL/redirect validation and API 23+ Media3 playback.
- Host transport switching and settings persistence, legacy RCC media-key behavior, and 0.2.10 metadata/artwork support.
- User-facing Chinese labels/status text and the debug app label are resource-backed; localized display labels do not alter internal transport identifiers.
- Official app identity (`com.shihab.diplay`, code 29, release name 0.2.10). No OEM identity, factory service, or vendor binary was added.

## Remaining boundary

API 18 coverage is based on the Android 4.3 emulator and the debug compatibility probe. It does not prove integration against every vendor USB/NCM stack or vehicle head unit. In particular, a target unit's OEM Apple services can own USB mode, multicast discovery, or audio resources; those interactions require testing on that hardware. Unsupported optional features must continue to report their API limitation without blocking the basic USB host.
